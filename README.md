# Карта угроз

Демонстрационное веб-приложение: интерактивная карта террористических инцидентов
на территории РФ, 1991–2026.

## Возможности

- Карта России (Leaflet + OpenStreetMap) с маркерами инцидентов
- Клик по маркеру — карточка с датой, типом, регионом, числом жертв и статусом
- Фильтры по регионам и типу инцидента (в т.ч. можно скрыть весь слой «Удары БПЛА» одним кликом)
- Диапазон лет (двойной слайдер)
- «Режим хронологии»: слайдер и кнопка воспроизведения — инциденты появляются
  по годам (накопительно или только текущий год)
- Слой «Удары БПЛА» с автообновлением: приложение раз в 5 минут опрашивает
  `drone-strikes.json` и добавляет новые записи без перезагрузки страницы

## Данные

**Теракты** — набор в [`data.js`](data.js) собран вручную по открытым источникам
(СМИ, справочные материалы) и носит демонстрационный характер: цифры жертв —
ориентировочные, статусы расследований упрощены, координаты приближены к
населённому пункту. Для точных и юридически значимых сведений используйте
официальные источники (СК РФ, судебные акты, специализированные базы вроде
Global Terrorism Database).

**Удары БПЛА** — набор в [`drone-strikes.json`](drone-strikes.json) собирается
по открытым новостным источникам (Fontanka.ru, KP.ru, Ura.news, Lenta.ru,
Ptoday.ru и др.) и обновляется периодической автоматизированной задачей (см.
ниже). В набор попадают только инциденты с конкретным названным
объектом/населённым пунктом — ежедневные сводки вида «сбито N БПЛА за ночь»
без указания, что именно пострадало, не включаются, поэтому набор **не
претендует на полноту** и не отражает вообще все удары (их количество
значительно больше). Это сводка уже произошедших и опубликованных в СМИ
событий, а не оперативные/прогнозные
данные. Первоначальные сообщения в условиях быстро меняющейся обстановки могут
уточняться или опровергаться; координаты приближены к населённому
пункту/объекту, не являются точными координатами падения.

### Автообновление drone-strikes.json

Файл `drone-strikes.json` имеет вид:

```json
{
  "generated_at": "ISO-время последнего обновления",
  "note": "...",
  "strikes": [ { "id": "...", "date": "YYYY-MM-DD", "name": "...", "region": "...",
                 "coords": [lat, lon], "target": "...", "killed": 0, "injured": 0,
                 "status": "...", "description": "...", "source": "..." } ]
}
```

Фронтенд подтягивает его сначала с
`https://raw.githubusercontent.com/IIIypuk-hash/TMap/main/drone-strikes.json`
(поэтому обновления попадают на карту сразу после коммита в этот репозиторий,
даже без передеплоя приложения), а если это недоступно — с локального
`drone-strikes.json` рядом с `index.html`.

**Ночи ПВО (агрегат по регионам)** — второй, отдельный набор в
[`drone-aggregate.json`](drone-aggregate.json): пересказ ежесуточных сводок
Минобороны РФ о перехваченных БПЛА. В отличие от `drone-strikes.json`, здесь
**не известна точка падения** — только факт, что над конкретным регионом в
конкретную ночь отражалась атака (плюс число сбитых по региону, если источник
его называет). Каждая запись `{date, region, count?}` рендерится отдельным,
более мелким и полупрозрачным маркером с детерминированным (не случайным при
каждой загрузке, а завязанным на дату+регион) смещением вокруг
административного центра региона — иначе десятки ночей по одному региону
легли бы в одну точку. Это отдельный тип в фильтре («Ночь ПВО (агрегат по
региону)») и отдельная секция в боковой панели со своим автообновлением.
Покрытие — по мере сбора, начали с августа 2026 (25 из 25 ночей), более
ранние месяцы будут добавляться постепенно: удары БПЛА по России происходят
почти каждую ночь с начала 2026 года (суммарно десятки тысяч аппаратов), и
готового сводного архива по дням/регионам нигде не существует — приходится
собирать вручную/полуавтоматически, сводка за сводкой.

## Запуск

Приложение полностью статическое (HTML/CSS/JS), достаточно любого веб-сервера:

```bash
python -m http.server 8642
```

и открыть `http://localhost:8642`. Для тайлов карты (OpenStreetMap) и
библиотеки Leaflet нужен доступ в интернет.
