# TMap · служебный модуль (фронтенд)

Статические страницы для внутреннего инструмента — рапорты, карта дел с
разграничением по уровню допуска, админка. Не связаны с публичной демо-картой
(`../index.html`) — отдельный модуль, отдельный CSS/JS, работает через API
бэкенда из `../backend`.

## Страницы

| Файл | Кто | Что делает |
|---|---|---|
| `login.html` | все | вход по логину/паролю |
| `report.html` | все | подать рапорт одним свободным текстом (без разбивки по полям) → ИИ формирует готовый документ по шаблону → сотрудник смотрит результат, при необходимости поправляет заголовок/категорию и точку на мини-карте, и подтверждает отправку |
| `map.html` | commander, staff, admin | карта дел (видимость — по роли), статус, ручная коррекция точки |
| `admin.html` | admin | шаблон рапорта, отделения, пользователи |

## Быстрый тест без установки на свой компьютер (GitHub Codespaces)

1. На странице репозитория нажмите зелёную кнопку **Code** → вкладка
   **Codespaces** → **Create codespace on main**.
2. Подождите 1–2 минуты — окружение соберётся, зависимости бэкенда
   поставятся и оба сервера (бэкенд на 8000, эта статика на 8642) запустятся
   в фоне автоматически (см. [`.devcontainer/`](../.devcontainer)).
3. Откроется уведомление о проброшенном порте 8642 — жмите **Открыть в
   браузере** (или вкладка **PORTS** внизу VS Code → порт 8642 → значок
   глобуса).
4. Дальше как обычно: `login.html`, `admin` / `change-me-too`.
   `AI_STUB_MODE=true` включён по умолчанию — рапорты оформляются без
   реального ключа Anthropic (см. `../backend/README.md`).

Важно: это **только для тестирования**. Каждый новый codespace — чистая
база данных (все дела/пользователи, кроме сисадмина, стираются). У
личного аккаунта GitHub есть бесплатный лимит часов в месяц — не забывайте
останавливать codespace (**Codespaces** → `···` → **Stop codespace**),
когда не тестируете, чтобы не тратить его впустую.

## Запуск на своём компьютере

1. Поднимите бэкенд (см. `../backend/README.md`):

   ```bash
   cd ../backend
   uvicorn app.main:app --reload --port 8000
   ```

2. Отдайте эту папку как статику на порту 8642 (он уже разрешён в
   `CORS_ORIGINS` бэкенда по умолчанию):

   ```bash
   cd ../ops
   python -m http.server 8642
   ```

3. Откройте `http://localhost:8642/login.html`. Первый вход — сисадмин,
   логин/пароль из `.env` бэкенда (`BOOTSTRAP_ADMIN_USERNAME` /
   `BOOTSTRAP_ADMIN_PASSWORD`).

4. Под сисадмином: создайте отделения (`admin.html`), затем пользователей
   (укажите роль и отделение), при необходимости поправьте шаблон рапорта.

Адрес бэкенда для фронтенда задан в [`api.js`](api.js) константой
`API_BASE` — поменяйте при разворачивании на боевом стенде (свой домен,
HTTPS).

## Важно перед боевым использованием

- Сейчас страницы отдаются как обычная статика без HTTPS — в таком виде
  логины/пароли и токены идут открытым текстом. Для реальной эксплуатации
  нужен HTTPS (обратный прокси с сертификатом) на обоих — бэкенде и
  фронтенде.
- Токен JWT хранится в `localStorage` — стандартный подход для такой
  простой схемы, но помните, что доступ к нему получит любой JS,
  выполнившийся на этой странице (в частности — при XSS). Рапорты
  рендерятся через экранированный HTML (см. `render_template` в бэкенде),
  так что сам текст рапортов не может внедрить скрипт.
- `ANTHROPIC_API_KEY` должен быть задан в `.env` бэкенда — без него
  отправка рапортов вернёт ошибку 502.
