# TMap backend — рапорты и уровни допуска

Внутренний бэкенд для подачи рапортов сотрудниками, автоматического
оформления их через Claude по шаблону и отображения точек на карте с
разграничением по уровню допуска.

## Роли

| Роль | Кто | Видит дела |
|---|---|---|
| `employee` | сотрудник, выезжающий на вызов | только свои |
| `commander` | командир отделения | все дела своего отделения |
| `staff` | штаб | все дела всех отделений |
| `admin` | сисадмин | всё + управление шаблоном, отделениями, пользователями |

## Установка

```bash
cd backend
python -m venv .venv
.venv\Scripts\activate      # Windows
pip install -r requirements.txt
copy .env.example .env
```

Заполните `.env`: как минимум `SECRET_KEY`, `BOOTSTRAP_ADMIN_PASSWORD`.
Для локальной разработки `DATABASE_URL` можно оставить как есть
(SQLite-файл появится сам). Для боевого стенда укажите Postgres:
`postgresql+psycopg2://user:password@host:5432/tmap`.

Пока нет платного ключа `ANTHROPIC_API_KEY` — поставьте `AI_STUB_MODE=true`.
Рапорт тогда оформляется простой эвристикой (ключевые слова для категории,
regex для адреса) вместо вызова ИИ — весь путь (рапорт → правка полей →
точка на карте → сохранение дела) можно проверить бесплатно. Когда ключ
появится — впишите его в `ANTHROPIC_API_KEY` и поставьте `AI_STUB_MODE=false`
(или уберите строку).

## Запуск

```bash
uvicorn app.main:app --reload --port 8000
```

При первом запуске автоматически создаются: одно отделение
(«Отделение №1»), сисадмин (логин/пароль из `.env`) и стандартный шаблон
рапорта. Дальше сисадмин заходит под своей учёткой и через `/admin/*`
создаёт отделения, сотрудников и правит шаблон.

Документация API (Swagger): `http://localhost:8000/docs`.

## Как это работает

Подача рапорта — в два шага, чтобы сотрудник мог проверить и поправить то,
что придумал ИИ, прежде чем это уйдёт в дело:

1. **`POST /reports/preview {"text": "..."}`** — черновик, ничего не
   сохраняет. Бэкенд берёт активный шаблон рапорта (HTML с полями вида
   `{{location}}`), отправляет текст сотрудника и список полей шаблона в
   Claude, получает: заполненные поля, заголовок дела, категорию, строку
   для геокодирования места и запасные координаты. Место геокодируется
   через Nominatim (OpenStreetMap, тот же провайдер, что и тайлы карты);
   если не найдено — используются запасные координаты от ИИ, а черновик
   помечается `needs_manual_location`. Ответ — `ReportDraft`: поля, категория,
   отрендеренный HTML, координаты и флаг `needs_manual_location`, которые
   фронтенд показывает сотруднику для правки (включая точку на мини-карте,
   если координаты не определены).
2. **`POST /reports`** (`ReportConfirmRequest`) — сохраняет черновик,
   возможно отредактированный сотрудником (поля, категория, координаты),
   как дело/документ. ИИ повторно не вызывается. Создаётся (или дополняется,
   если передан `case_id`) дело — `Case` — и документ `Document` с готовым
   HTML-рапортом.

`GET /cases` отдаёт список дел, отфильтрованный по роли текущего
пользователя. `GET /cases/{id}` — карточку дела со всеми документами.

## Шаблон рапорта

Хранится как HTML с плейсхолдерами `{{имя_поля}}`. Сисадмин правит его через
`PUT /admin/template`. Любые плейсхолдеры в шаблоне автоматически передаются
в ИИ как список полей для заполнения. Есть несколько системных полей,
которые заполняются кодом (не ИИ), если использованы в шаблоне: `date`,
`officer_name`, `unit_name`, `category_label`, `location`.
